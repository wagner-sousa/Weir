# Implementation Plan: JSON-to-TOON Response Conversion

**Branch**: `013-json-toon-conversion` | **Date**: 2026-07-06 | **Spec**: [spec.md](spec.md)

**Input**: [02-plan-prompt.md](../../02-plan-prompt.md)

## Summary

Add a TOON (Token-Oriented Object Notation) conversion layer in the Weir proxy pipeline that transparently optimizes MCP tool call responses. Supports three output modes: `dynamic` (compare JSON vs TOON, return smaller), `json` (pass through), `toon` (always convert). Configurable via `WEIR_TOON_*` env vars (hot-read at conversion time) and optional per-backend `outputMode` in `.mcp.json`. Savings are logged via pino; no dashboard or persistence.

## Technical Context

**Language/Version**: Node.js 22 (ESM), TypeScript 5.7+, NodeNext module resolution

**Primary Dependencies**: `@toon-format/toon ^2.3` (new), `gpt-tokenizer ^3.4` (new), `zod 3.24` (existing), `pino 9` (existing)

**Storage**: N/A — savings logged via pino only

**Testing**: Vitest 3 (unit: `tests/unit/toon-converter.test.ts`, `tests/unit/optimizer.test.ts`, `tests/unit/stats.test.ts`, `tests/unit/outputMode-resolution.test.ts`)

**Target Platform**: Linux (Docker), Node.js 22+

**Project Type**: CLI proxy (backend-only feature, no frontend changes)

**Performance Goals**: TOON encode/decode adds <5ms p99 per response; comparison in dynamic mode <10ms p99

**Constraints**: <50ms total added latency per response; must not block the forwarding pipeline; hot-read env vars (no watcher)

**Scale/Scope**: Single gateway instance; no multi-node concerns
